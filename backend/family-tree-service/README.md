# family-tree-service

Universal family and heritage archive. Records people, names, parentage, unions,
care relationships, heritage events, and the claims plus evidence that justify them.

- Java 21, Spring Boot 3.4.0, Postgres 16, Flyway, Hibernate `validate`.
- No H2, no Kafka, no Lombok. The schema is owned by Flyway migrations.

## Run it

```powershell
.\run.ps1
```

That builds the jar, starts Postgres with Docker, and serves on port 8085 (foreground).

To start the database, API and UI together in the background:

```powershell
.\start-local.ps1
```

- API base: `http://localhost:8085/api/v1`
- Swagger UI: `http://localhost:8085/swagger-ui.html`
- Health: `http://localhost:8085/actuator/health`

Manual equivalent:

```powershell
docker compose up -d familytree-db
$env:DB_URL="jdbc:postgresql://localhost:5432/familytree"
$env:DB_USERNAME="familytree"; $env:DB_PASSWORD="familytree"
java -jar target/family-tree-service-1.0.0.jar
```

## Test it

```powershell
docker compose up -d familytree-db-test
.\mvnw.cmd verify
```

Tests run against real Postgres on port 5433 (`familytree_test`). They cover the
acceptance rules FT-001 to FT-013, including the SQL-only invariants that a unit
test cannot see.

| GET | `/api/v1/persons/{id}/ancestry` | Walk parentage upward |
| POST | `/api/v1/families` | Create a family group |

| POST | `/api/v1/parentages` | Record parentage (4 identity states) |
| POST | `/api/v1/parentages/{id}/supersede` | Identify an unknown parent |
| POST | `/api/v1/unions` | Record a union with 2+ participants |

| GET | `/api/v1/audit/{entityType}/{entityId}` | Audit trail for one record |

## Rules the code enforces

1. **Membership is explicit.** Parentage never creates a family membership.
2. **Care is not parentage.** A guardian is a guardian.
3. **Four parent identity states:** `IDENTIFIED`, `UNIDENTIFIED`, `UNRECORDED`, `UNKNOWN`.
4. **At most two active biological parents**, one per role.
5. **Names are never overwritten.** A change closes the old row.
6. **Claims carry evidence**, people do not.
7. **Supersede, never delete.** Old parentage stays with `superseded_by_id`.
8. **Audit log is append-only** (enforced by a Postgres trigger).
9. **UUIDv7 ids**, generated by the application, so inserts stay ordered.

## Not in Phase 1

- Authentication and RLS. Every write falls back to the seeded system contributor.
- Binary storage. `document.storage_key` is a placeholder for object storage.
- File upload. Checksums are validated, but bytes are not stored.
- Merge tooling beyond `Person.mergeInto`.

## Layout

```
src/main/java/com/platform/familytree/
  identity/   people, names, archive
  family/     groups, membership, parentage, unions, care
  heritage/   locations, events, organisations
  evidence/   sources, documents, claims
  community/  contributors, permissions, invitations, consent, review
  shared/     ids, errors, audit
src/main/resources/db/migration/   V1..V9 + R__views
```
